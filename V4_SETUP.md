# InsightForge AI — v4 Frontend

A responsive three-column React/TypeScript interface connected to the **existing** Ollama/Pandas/ML Python modules.

## What this adds

- Left navigation: Overview, AI Analyst, Datasets, ML Studio shortcuts, Reports/exports, recent chat sessions, and Settings.
- Center: natural-language AI chat, suggested prompts, follow-up questions, verified responses.
- Right: drag-and-drop CSV/Excel **or folder**, click-to-browse, active dataset stats, compact chart/data visualization dock.
- Resizable sidebar, right panel, and top/bottom right split using mouse drag. Double-click divider to reset. Preferences persist in browser storage.
- Download CSV / latest chart PNG, pin current visualization, expand and shrink chart without horizontal page scrolling.
- Your original `app.py`, `llm_client.py`, query planner, analysis engine, visualization, and tests remain untouched.

### Current scope / known limits

- v4 uses one active dataset per analysis session, consistent with the existing Python engine. A folder or multiple files can be imported and switched via the Active Dataset menu, but the analysis engine handles only one table at a time; multi-table joins are not implemented. Supported files: CSV, XLSX and XLS, up to 25 MB per file and 20 files per selection.
- Charts are generated by the existing **Matplotlib** engine and are automatically scaled inside a resizable container. They are not yet interactive Plotly/Recharts charts.
- Chat history survives navigation and page refresh **as long as the local backend process is still running**. The backend holds uploaded datasets and conversations in RAM; browser storage keeps panel sizes and chat titles, not dataset contents.
- Overview and Dataset Explorer are functional; ML Studio exposes shortcuts into existing analytical tasks. A fully separate AutoML/SHAP interface and automatic PDF reports are future work.
- The backend API is intended for **local development only**; it binds to `127.0.0.1`. Do not expose it to the public internet without authentication, persistent session management, and stronger upload controls.
- Since one analysis result may mutate the dataset, use the export button to save changes.

## Install on a NEW `v4` branch (Windows PowerShell)

From your existing local project directory:

```powershell
cd C:\Users\LOQ\Ai-Data-Analyst-Agent-ML-Project
git switch v0
git pull origin v0
git switch -c v4
```

If `v4` already exists locally, use `git switch v4` instead. **Do not run `git add .`** because you have untracked export CSVs.

Extract `InsightForge_v4_overlay.zip` into the **project root**, so `insightforge_api.py` is beside `app.py`, and `frontend` is inside the same root. Do not copy the extra folder `insightforge_v4` around the files; extract the *contents*.

### Terminal 1 — Python API

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-v4.txt
.\.venv\Scripts\python.exe -m uvicorn insightforge_api:app --host 127.0.0.1 --port 8000 --reload
```

Keep this terminal running. Health/status available at http://127.0.0.1:8000/api/health.

### Terminal 2 — React UI

```powershell
cd C:\Users\LOQ\Ai-Data-Analyst-Agent-ML-Project\frontend
npm install
npm run dev
```

Open **http://127.0.0.1:5173**. If PowerShell says `npm` is not recognized, install Node.js LTS first, then restart PowerShell.

Ollama must be installed and `qwen3:4b-instruct` available as before. The original `.env` controls the model.

Optional backend smoke check (Terminal 1 can keep running):

```powershell
.\.venv\Scripts\python.exe v4_smoke_test.py
```

### Push only the new implementation

From the project root, after testing upload + chat + visualization:

```powershell
git status
git add insightforge_api.py requirements-v4.txt V4_SETUP.md v4_smoke_test.py frontend
git diff --cached --stat
git commit -m "Build InsightForge v4 three-panel frontend and FastAPI bridge"
git push -u origin v4
```

Your existing `v0` and `main` branches remain unchanged. The `frontend/.gitignore` excludes `node_modules/`, `dist/` and TypeScript build-info from commits.

### Troubleshooting

- Browser says "This site can't be reached": ensure `npm run dev` is still running and visit the exact URL shown in its terminal.
- Model status says offline: run `ollama ps`, check `.env`, and make sure Ollama desktop/server is running.
- UI says backend unavailable: ensure Terminal 1 is running and port 8000 is not blocked.
- Tests for existing code: `.\.venv\Scripts\python.exe -m unittest discover -s tests` from the root.
